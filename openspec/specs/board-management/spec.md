# board-management Specification

## Purpose
Управление канбан-досками: создание, чтение, переименование и удаление. Доступ осуществляется по секретному slug без авторизации. Доски автоматически удаляются после 30 дней отсутствия активности.

## Requirements

### Requirement: REQ-BM-1 — Создание доски

Система SHALL создавать доску с уникальным slug из 8 строчных буквенно-цифровых символов, именем «Моя доска», цветом `#B69CFF` и тремя колонками. Для генерации slug MUST использоваться криптографически стойкий источник случайности.

#### Scenario: Успешное создание

- **WHEN** клиент отправляет `POST /api/boards` без тела
- **THEN** сервер возвращает 201 и `{ "slug": "a7f3b9c1", "name": "Моя доска", "color": "#B69CFF", "url": "/#/a7f3b9c1" }`
- **AND** `created_at` и `updated_at` равны текущему времени
- **AND** колонки имеют стабильные идентификаторы и порядок: `todo` / «Сделать», `progress` / «Делаю», `done` / «Готово»

#### Scenario: Коллизия slug

- **WHEN** сгенерированный slug уже существует, включая soft-deleted доски
- **THEN** сервер генерирует новый slug и повторяет попытку
- **AND** после ограниченного числа неудач возвращает 503, не создавая частичных данных

### Requirement: REQ-BM-2 — Получение состояния доски

Любой клиент, знающий slug, SHALL получить полное состояние активной доски.

#### Scenario: Полное состояние

- **WHEN** клиент отправляет `GET /api/boards/:slug`
- **THEN** сервер возвращает 200 и объект со следующими полями:
  ```json
  {
    "slug": "a7f3b9c1",
    "name": "Релиз v2",
    "color": "#B69CFF",
    "updatedAt": "2026-11-17T12:00:00.000Z",
    "columns": [{ "id": "todo", "title": "Сделать", "order": 0 }],
    "tasks": [],
    "users": [{ "name": "Аня", "color": "hsl(42, 65%, 60%)" }],
    "drafts": []
  }
  ```
- **AND** возвращаются только черновики текущего клиента по серверному `clientId` из cookie
- **AND** задачи отсортированы по `order`, затем `createdAt`, колонки — по `order`

#### Scenario: Доска недоступна

- **WHEN** доска не существует или имеет `deleted_at`
- **THEN** любой board-scoped endpoint возвращает 404 `{ "error": "Доска не найдена" }`
- **AND** состояние soft-deleted доски не раскрывается

### Requirement: REQ-BM-3 — Переименование доски

Любой участник SHALL иметь возможность изменить имя доски на непустую строку длиной до 80 символов после trim.

#### Scenario: Успешное переименование

- **WHEN** клиент отправляет `PATCH /api/boards/:slug` с `{ "name": "Релиз v2" }`
- **THEN** сервер возвращает обновлённую доску и обновляет `updated_at`
- **AND** подключённые клиенты получают `board_updated`

#### Scenario: Некорректное имя

- **WHEN** имя пустое или длиннее 80 символов
- **THEN** сервер возвращает 400 и не меняет данные

### Requirement: REQ-BM-4 — Удаление доски

Любой, у кого есть slug, SHALL иметь возможность удалить доску. Ручное и автоматическое удаление используют soft delete записи Board и hard delete связанных Task, BoardUser и ParsedDraft в одной транзакции.

#### Scenario: Ручное удаление

- **WHEN** клиент отправляет `DELETE /api/boards/:slug` после явного подтверждения на клиенте
- **THEN** сервер возвращает 204, устанавливает `deleted_at` и удаляет связанные данные
- **AND** доска становится недоступной для всех участников по старой ссылке, а не только для инициатора
- **AND** активные SSE-клиенты получают `board_deleted` с `{ "reason": "manual" }`, после чего поток закрывается
- **AND** повторный DELETE возвращает 404; восстановление через публичный API невозможно

### Requirement: REQ-BM-5 — Автоудаление неактивных досок

Планировщик SHALL один раз в сутки помечать удалёнными доски, у которых `updated_at < now() - 30 дней`, и отправлять `board_deleted` с `{ "reason": "inactivity" }`.

#### Scenario: Неактивная доска удаляется

- **GIVEN** `updated_at` доски раньше 30-дневного cutoff
- **WHEN** запускается очистка
- **THEN** выполняется то же soft delete, что при ручном удалении

#### Scenario: Активность продлевает срок

- **WHEN** создана/изменена/удалена задача, финализирован черновик, изменено имя или пользователь присоединился к доске
- **THEN** `updated_at` доски обновляется
- **AND** чтение доски, SSE-подключение, discard и повторный join существующего пользователя активностью не считаются

### Requirement: REQ-BM-6 — Присоединение к доске

Клиент SHALL присоединяться к доске именем длиной 1–40 символов после trim. Пара `(boardId, name)` уникальна; повторный join возвращает существующего пользователя без нового SSE-события.

#### Scenario: Новый участник

- **WHEN** отправлен `POST /api/boards/:slug/join` с `{ "name": "Аня" }`
- **THEN** сервер возвращает 201 и `{ "name": "Аня", "color": "hsl(...)" }`
- **AND** цвет детерминированно вычисляется из имени
- **AND** `updated_at` доски обновляется и рассылается `user_joined`

#### Scenario: Повторный join

- **WHEN** участник с таким именем уже существует
- **THEN** сервер возвращает 200 и существующего пользователя
- **AND** дубликат и событие `user_joined` не создаются

### Requirement: REQ-BM-7 — Краткие метаданные для списка досок

Система SHALL возвращать актуальные метаданные для переданного набора slug, не раскрывая полное содержимое досок.

#### Scenario: Пакетное получение

- **WHEN** клиент отправляет `POST /api/boards/summaries` с `{ "slugs": ["a7f3b9c1"] }`, не более 100 slug
- **THEN** сервер возвращает 200 и массив найденных активных досок: `{ "boards": [{ "slug": "a7f3b9c1", "name": "Релиз v2", "color": "#B69CFF", "updatedAt": "...", "totalTasks": 6, "doneTasks": 1 }] }`
- **AND** отсутствующие и удалённые slug возвращаются отдельно в `missingSlugs`
- **AND** запрос не изменяет `updated_at`

### Requirement: REQ-BM-8 — Административный список досок

Административный endpoint SHALL быть доступен только по секрету из конфигурации сервера.

#### Scenario: Доступ разрешён

- **WHEN** отправлен `GET /admin/boards` с корректным `X-Admin-Secret`
- **THEN** возвращаются активные и удалённые доски со slug, именем, `created_at`, `updated_at`, `deleted_at` и количеством задач

#### Scenario: Доступ запрещён

- **WHEN** секрет отсутствует или неверен
- **THEN** сервер возвращает 401 одинакового вида, не раскрывая данные
